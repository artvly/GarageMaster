# Архитектура «Гараж Мастер»

Документ фиксирует проектные решения по утверждённому ТЗ (`docs/Волынкин_курсовая_ТРПС.pdf`, 7 листов).
Он же — основа для разделов РПЗ «Структурная схема ПО» и «Диаграммы классов».

## 1. Объём (по ТЗ)

**Менеджер / приёмщик:** клиенты; автомобили (госномер, марка, модель, VIN, год, пробег);
заказ-наряды (создание, редактирование, удаление, поиск, фильтр по статусу и дате);
статусы «Принят → В работе → Готов к выдаче → Выдан» с отменой и возвратом;
каталог услуг; склад со списанием в заказ; печать заказ-наряда и акта выполненных работ.

**Администратор:** пользователи и роли (Администратор, Менеджер); отчёты — выручка за период
и список выполненных работ; резервное копирование (вручную и при закрытии); экспорт в CSV.

**Надёжность:** контроль ввода, блокировка некорректных действий, транзакции и внешние ключи SQLite.

**Вне объёма** (было в черновике ТЗ, в утверждённую версию не вошло): календарь загрузки постов,
QML, экспорт в XLSX, отчёт по загруженности мастеров, редактируемые справочники статусов,
роль «механик».

## 3. Слои

```
┌──────────────────────────────────────────────────────────┐
│ UI — Qt Widgets            src/app                       │
│   MainWindow, LoginDialog, *View (вкладки), *Dialog      │
├──────────────────────────────────────────────────────────┤
│ Модели представления       src/app/models                │
│   QAbstractTableModel + QSortFilterProxyModel            │
├──────────────────────────────────────────────────────────┤
│ Сервисы (бизнес-правила)   src/core/services             │
│   AuthService, ClientService, OrderService,              │
│   StockService, ReportService, CsvExporter, PrintService │
├──────────────────────────────────────────────────────────┤
│ Репозитории (SQL)          src/core/data                 │
│   UserRepo, ClientRepo, CarRepo, CatalogRepo,            │
│   PartRepo, OrderRepo                                    │
├──────────────────────────────────────────────────────────┤
│ Инфраструктура             src/core/data, security       │
│   Database (PRAGMA, миграции), BackupService,            │
│   PasswordHasher                                         │
└──────────────────────────────────────────────────────────┘
          domain/ — сущности, OrderStatus, Money (используются всеми слоями)
```

Правила:

1. **SQL только в репозиториях и инфраструктуре.** UI не создаёт `QSqlQuery`.
2. **Правила — в сервисах.** Переходы статусов, списание склада, запрет удаления клиента
   с открытыми заказами, проверка ролей. Многошаговые операции — одна транзакция.
3. **`garage_core` не зависит от Qt Widgets** — поэтому сервисы и репозитории покрываются
   тестами без GUI. Печать (`PrintService`) живёт в `app`, т.к. требует `QPrinter`.
4. Для простых справочников (каталог услуг) допускается `QSqlTableModel` — без бизнес-логики.

## 5. База данных

Схема — `src/core/resources/migrations/001_init.sql`.

```
users ─┐
       ├─< orders >── clients ──< cars
       │     │  └──< order_status_history
       │     ├──< order_services >── service_catalog
       │     └──< order_parts >───── parts ──< stock_movements
```

- **Деньги — целые копейки** (`*_kop INTEGER`), в C++ — `gm::money::Kopecks` (qint64).
- **Снимок цены:** строки заказа хранят название и цену на момент добавления.
- **Итог заказа не хранится**, а считается (представление `order_totals`, `Order::total()`).
- **Склад:** `parts.quantity` — текущий остаток (`CHECK >= 0` не даст уйти в минус),
  `stock_movements` — журнал: приход, списание в заказ, возврат при отмене, корректировка.
- **Удаление:** клиента с автомобилями/заказами и запчасть, использованную в заказах,
  удалить нельзя (`ON DELETE RESTRICT`); строки заказа удаляются вместе с заказом (`CASCADE`).
- **Миграции:** `PRAGMA user_version` + файлы `NNN_*.sql`; каждая — в своей транзакции.
  БД от более новой версии программы не открывается.
- **PRAGMA при подключении:** `foreign_keys=ON`, `journal_mode=WAL`, `synchronous=NORMAL`.
- Файл БД: `%APPDATA%\GarageMaster\GarageMaster\garage.sqlite`.

## 6. Ключевые решения

**Статусы заказа** — конечный автомат (`domain/OrderStatus`):

```
Принят ──► В работе ──► Готов к выдаче ──► Выдан
  │  ▲        │   ▲          │
  │  └────────┘   └──────────┘   (возврат на шаг назад)
  ▼               │
Отменён ◄─────────┘ (из «Принят» и «В работе»)
```

Отмена возвращает запчасти на склад в той же транзакции. В «Выдан» и «Отменён» состав заказа
не редактируется. Каждый переход пишется в `order_status_history`.

**Списание запчастей** — в момент добавления в заказ (как в ТЗ): одна транзакция
`order_parts` + `parts.quantity -= n` + `stock_movements`. Удаление строки/отмена — обратная операция.

**Вход и роли.** ТЗ разграничивает роли, значит нужен вход. Пароли — PBKDF2-HMAC-SHA256,
100 000 итераций, соль 16 байт (`security/PasswordHasher`). При первом запуске создаётся
`admin / admin` с обязательной сменой пароля.

**Резервная копия** — `VACUUM INTO` (согласованный снимок даже в WAL-режиме):
вручную через меню и автоматически при закрытии; хранятся 10 последних.

**Печать** — HTML-шаблоны из ресурсов → `QTextDocument` → `QPrintPreviewDialog` (A4).

**Экспорт** — CSV в UTF-8 с BOM и разделителем `;` (корректно открывается в русском Excel).

## 8. Сборка

**Qt Creator:** «Открыть проект» → `CMakeLists.txt` → набор *Desktop Qt 6.5.3 MinGW 64-bit* → Собрать.
Тесты: «Инструменты → Тесты → Запустить все» или `ctest` в папке сборки.

**Командная строка** (Qt и MinGW в PATH):

```bat
cmake -S . -B build -G Ninja -DCMAKE_PREFIX_PATH=C:/Qt/6.5.3/mingw_64 -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```
